# 🚀 5-Store Pilot Beta Program — Product Spec

## Executive Summary

Launch a **closed-loop pilot with 5 SMB retail/F&B stores** to validate product-market fit before broad launch. Each pilot gets:
- **30-day trial** (Sep 25 – Oct 25, 2026)
- **Live support + daily check-ins** (Telegram group + WhatsApp)
- **Free tier upgrade → Pro 30 days** (waived Rp 249k/month fee)
- **Feedback loop** (weekly surveys, feature requests, UX friction)
- **Referral reward** (Rp 500k store credit if refer 2+ friends)

---

## 🎯 Pilot Goals

### Primary Objectives
1. **Adoption Velocity**: Track DAU/WAU across dashboard, inventory, payroll modules
2. **Feature Utilization**: Which features drive engagement? What's friction?
3. **Revenue Model Validation**: At end of trial, how many convert to paid? At what price point?
4. **Brand Advocacy**: Net Promoter Score (NPS) + referral behavior

### Secondary Objectives
- Identify missing features (WhatsApp, API, multi-location support)
- Collect testimonials + case studies for marketing
- Build champion customers for future upsell (enterprise, consulting)

---

## 📋 Pilot Store Selection Criteria

### Requirements (All Must-Have)
- **Vertical**: F&B (resto, kafe) OR Retail (fashion, convenience, electronics)
- **Size**: 5–50 employees (sweet spot for APEX positioning)
- **Location**: Jakarta, Bandung, or Surabaya (for support timezone)
- **Commitment**: Owner/manager agrees to daily 5-min check-in (Telegram) + weekly 30-min Zoom

### Preference (Nice-to-Have)
- Already using Excel/manual payroll (easier wins vs. competitor switching)
- Social media presence (Instagram, TikTok) for testimonial/case study sharing
- Founder warm intro (vs. cold outreach)

---

## 📦 Onboarding Kit (Per Store)

### 1. Welcome Package (T-0: Kickoff)
**Deliverables**:
- Personalized welcome video (Loom, 3-min): "Why APEX, how it works, what to expect"
- Onboarding checklist (Notion, shared):
  - [ ] Create company profile + upload logo
  - [ ] Add roster (employees + roles)
  - [ ] Configure shift templates
  - [ ] Test first payroll calculation (demo data provided)
  - [ ] Invite 1-2 managers as viewers
- Telegram group: `APEX-Pilot-[StoreName]` (store owner + Pam + 1 support lead)
- Quick-start guide (PDF, IDN): 5 pages, screenshots + walkthroughs

### 2. Daily Support (T+0 to T+30)
**Commitment**:
- **Async**: Telegram group, max 2-hour response time (9 AM–6 PM Jakarta)
- **Sync**: Optional Friday 3 PM Zoom (30 min, all pilots + APEX team)
- **Escalation**: Critical bugs → Dwight (Lead Engineer) same-day fix

**Support Scripts**:
- "How to add employee to roster" (2-min video)
- "How to calculate and verify payslip" (3-min video)
- "How to fix attendance sync errors" (2-min video)
- "How to export data before leaving" (2-min video)

### 3. Weekly Pulse Survey (In-App, T+7, T+14, T+21, T+28)
**Questions** (5 min):
1. "How easy was it to use APEX this week?" (1–5 Likert)
2. "What frustrated you most?" (free text)
3. "What feature would help you most?" (free text)
4. "Would you recommend APEX to a friend?" (1–10 NPS)
5. "Price you'd pay if paying: Rp X/month?" (WTP validation)

## 📊 Acceptance Criteria & Metrics

### Success Thresholds (Go/No-Go Decision)

| Metric | Target | Why | Owner |
|--------|--------|-----|-------|
| **Adoption** | ≥ 4/5 stores active at T+7 | Baseline engagement | Pam |
| **Feature Use** | ≥ 60% use payroll module in first 2 weeks | Core value prop | Dwight |
| **NPS** | ≥ 7 (promoters > passives+detractors) | Product quality gate | Pam |
| **Churn** | ≤ 1 store drops out before T+30 | Commitment test | Ryan |
| **Conversion** | ≥ 3/5 stores convert to paid Pro at end | Revenue model validation | Ryan |
| **Time-to-Value** | ≤ 3 days to first payslip | UX friction detector | Dwight |
| **Support Load** | ≤ 15 hours/week per Pam | Scalability check | Pam |
| **Referral Rate** | ≥ 2 referrals / pilot store | Word-of-mouth viability | Ryan |

### No-Go Thresholds (Red Flags)
- **Adoption < 60%** → Product too complex, UX needs rework
- **NPS < 5** → Core value prop not resonating
- **Conversion < 40%** → Price too high or perceived value gap
- **Support load > 25 hrs/week** → Unit economics unsustainable at scale

## 🚨 Risk & Mitigation

|------|-----------|
